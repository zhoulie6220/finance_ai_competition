# 系统范围说明

本文说明系统**能做什么、不能做什么**。赛事要求「说明主要假设、适用范围和风险因素」，
划清边界不是示弱，而是分析严谨性的一部分——声称什么都能做的系统，通常什么都做不扎实。

---

## 一、适用对象

系统面向**国内 A 股能源钢铁行业**上市公司的年度报告，具体指申万口径下的
**钢铁、煤炭、石油石化**等重资产周期行业的一般工商企业。

### ⚠ 本次参赛的研究案例：只做钢铁

签字文档 A-9 已拍板：**细分行业选择钢铁（黑色金属冶炼和压延加工，长流程/综合钢企），
不选择煤炭。**

| | 决策 |
|---|---|
| 主公司 | 宝钢股份 |
| 可比公司 | 华菱钢铁、首钢股份 |
| 细分行业 | 钢铁——黑色金属冶炼和压延加工，长流程/综合钢企 |

理由是当前指标体系围绕钢铁建立：吨钢毛利的分母是**钢材销量**，产能利用率要求
**粗钢产量配粗钢有效产能、钢材产量配钢材有效产能**，年报披露结构（产销量表、
分产品毛利率表）也都是钢铁的写法。煤炭的对应口径是吨煤毛利与商品煤销量，
虽可参数化，但**不在本次范围内**。

需要说清楚的是「案例范围」与「系统能力」的区别：

- **案例范围**：本次只跑钢铁公司，演示与评测数据全部来自上述三家公司
- **系统能力**：引擎仍按 `rule_config.industry` 参数化，字典里保留煤炭字段
  （`coal_output` / `coal_sales_volume` / `coal_price_avg` / `ton_coal_gross_margin`），
  但**这些字段在本次演示中不会被填充**，界面上始终显示「未找到」

不删除煤炭字段的原因：删掉就真的失去了「引擎按行业参数化、不硬编码」这条设计主张的
证据；留着它们，评委看到的是一套**已参数化但当前只启用钢铁**的体系。
煤炭字段的 `scope_note` 里已注明本次不启用。

### 明确不支持

> **金融业（银行、保险、证券）不支持。**

不是因为「暂时没做」，而是因为报表结构与估值逻辑根本不同：

- 银行没有「营业成本」「存货」，资产端主要是金融资产，负债端是存款
- 保险的利润来源是承保与投资，与制造业的成本加成逻辑无关
- 证券公司的自营与经纪业务波动来自市场而非产能
- **FCFF / DCF 对金融机构本就不适用**——它们的价值来自资产负债表的利差与久期管理

一旦声称「支持全部 A 股」，评委随手拿一只银行股就能试穿。明确划出这条边界，
既是对评委的诚实，也是对自身工作量的保护。

### 行业参数化而非硬编码

引擎不硬编码任何单一公司规则。行业差异通过 `rule_config` 的 `industry` 字段参数化：

```sql
-- industry = '' 表示全局默认；填具体行业则只覆盖该行业
INSERT INTO rule_config VALUES
  ('valuation.terminal_growth_max', '0.02', 'percent', '',      ...),  -- 全局
  ('valuation.wacc_min',            '0.06', 'percent', 'steel', ...);  -- 钢铁覆盖
```

新增一个行业只需加一组阈值行，**不需要改代码**。

## 二、系统做什么

围绕一家上市公司三年年报与两家可比公司数据，完成一条完整投研链路：

```
上传年报与可比公司数据
      ↓
文档解析与财务字段提取（带单位、口径、页码）
      ↓
会计口径统一与三表勾稽校验
      ↓
MD&A 主张提取
      ↓
叙事—财务一致性诊断
      ↓
周期正常化 → DCF / 相对估值情景
      ↓
带证据链的买方投资备忘录
```

### 四个主流程 Skill

| Skill | 做什么 | 输出 |
|---|---|---|
| **S1 财报结构化提取与口径统一** | PDF 文本/表格解析、单位识别、报告期识别、页码绑定、合并/母公司口径统一 | 标准化财务事实表 |
| **S2 财务质量分析** | 同比环比、利润率、ROE、现金转化、应收账款、存货、商誉、减值、非经常性损益、三表勾稽 | 趋势表、异常清单、待核查问题 |
| **S3 MD&A 叙事一致性分析** | 提取可验证主张，匹配后续财务结果，计算兑现度与一致性 | 主张—事实对照表、诊断指数、风险提示 |
| **S4 情景估值与备忘录** | FCFF 为主的 DCF + PE/EV-EBITDA/PB 相对估值，三情景，敏感性分析 | 估值区间、关键假设、证伪条件、投资备忘录 |

### 一个质量控制功能

**研究报告纠错**（按需调用）：核查给定研报草稿中的数字、单位、期间、口径、估值倍数
与引用。

## 三、系统不做什么

明确排除，避免范围蔓延：

- ❌ **实盘交易与自动下单**
- ❌ **全市场实时行情与高频数据**
- ❌ **直接预测精确股价或承诺投资收益**
- ❌ **依赖付费数据库才能运行的核心功能**（核心链路只用公开渠道材料）
- ❌ **没有证据支撑的自动荐股**
- ❌ **金融业（银行/保险/证券）的公司分析**
- ❌ **把「叙事不一致」等同于「财务造假」**——系统只输出「存在证据支持的待核查风险」

---

## 四、三层输出结构

系统所有重要结论都拆为三层，页面与导出报告均明确标注：

| 层次 | 内容 | 来源 |
|---|---|---|
| **事实** | 原始报告披露的数字、原文与页码 | 年报，可核验 |
| **推论** | 程序计算出的同比、现金转化率、一致性分数、估值结果 | 确定性引擎，可复算 |
| **观点** | 投资逻辑、风险判断、情景倾向 | 研究判断，须标注为观点 |

这样做的目的是避免模型把推测写成财务事实。**报告中没有无来源的关键数字。**

## 五、主要假设

1. **年报数据真实可靠**——系统核验的是「管理层叙事与财务数据是否一致」，
   不核验财务数据本身的真实性。两者是不同的命题。

2. **同一指标在年报内多处出现时取多数一致值**——正文、主要指标表、三张主表、附注里
   的同一指标精度可能不同（正文写「约 123.5 亿元」，主表写 12,345,678,901.23 元）。
   系统记录每一次观测并交叉校验，分歧全部留痕。

3. **报表结构与一般工商企业一致**——见第一节的适用范围。

4. **周期正常化的窗口锚定最新完整年度**——不使用「2016—2023」这类不含最新年度的
   窗口，避免被质疑为人为挑选区间。

5. **相对估值的可比公司须同属细分行业**——煤价是钢企的成本项，两者周期驱动因素相反。
   把煤企当作钢企的估值可比公司，中位数会失去意义。

## 六、风险因素

### 数据与解析风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 中文年报表格解析准确率 | 跨页表、合并单元格、「其中：」层级行、负数括号、单位只在表头出现一次、扫描件无文本层 | 先定位报表区再抽值；行名别名表由会计同学维护；**用三表勾稽反查解析错误**——勾稽不平优先怀疑解析而非公司造假；黄金集 100 字段准确率作为回归门禁 |
| 输出精度误读 | 正文常带「约」「近」等模糊表述 | 原样保存 `value_raw`，保留原始单位与换算因子 |

**宁可显示「未找到」，绝不猜。**

### 模型风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| LLM 抽取不稳定 | 同一文本两次结果不同、JSON 漂移 | `temperature=0` + 固定 seed；强 JSON Schema 约束；Prompt 版本化 + 结果缓存 |
| LLM 改写数字 | 在组织文字时悄悄改动数值 | **数字守卫**：输出的任何数字必须在工具结果集合里找得到，否则拦截重写；Citation 锚点的 `number_ref` 与证据比对 |

### 方法与口径风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 跨口径计算 | 用合并口径与母公司口径混算增长率 | 口径是数据契约的一等字段；引擎硬断言，不一致时抛 `IncomparableError` |
| 重述值覆盖原始值 | 重述后数据替换掉原始披露值 | 双行并存，永不 UPDATE 覆盖 |
| 并购后同比当内生增长 | 合并范围变化导致的收入增长被误读 | 标记为「不可直接比较」，不进入正常化中枢 |
| 亏损公司机械使用 PE | 分母为负，倍数无意义 | `PE` 函数签名含 `profitable: bool`，亏损直接 `refused` |
| **把周期当作常态** | 在周期高点用虚高的 FCFF 做永续增长 | 见 `docs/03-valuation-rules.md` 的周期正常化硬规则 |

### 演示风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 现场断网 / API 不可用 | 决赛现场网络不可控 | `OFFLINE_MODE` 走预录制 LLM cassette，零网络跑完整链路 |

> **离线回放时界面必须显著标注「离线回放模式」。** 这是诚信问题，也正合赛事
> 「明确区分事实与观点」的精神——不得假装实时。

## 七、结论边界

系统在涉及管理层叙事时，一律使用审慎表述：

| ✅ 可以说 | ❌ 不可以说 |
|---|---|
| 存在证据支持的风险信号 | 管理层叙事虚假 |
| 需进一步核查 | 公司财务造假 |
| 该主张未获得后续财务数据支持 | 管理层在撒谎 |
| 数据不可比，无法判断 | （推断结论） |
| 置信度不足，建议人工复核 | （省略说明直接给结论） |

**诊断指数不作为单独的买卖信号。** 它只用于：识别未来业绩下修风险、透明地调整估值
情景权重或假设范围、生成持续跟踪指标、触发研究报告人工复核。

页面同时展示「支持证据」「冲突证据」「不可比原因」「置信度」和「人工复核」入口。
用户可查看、修改或恢复规则参数。

## 八、评测边界

- 标注集只用于**验证与展示**，不将小样本结果包装为普遍性的因果结论
- 测试数据与演示数据分开
- 按年份切分，避免未来信息泄漏
- AUC、Brier 等指标仅在样本量满足要求时补充报告，不作为主要创新依据
- 重点报告可复核的任务指标：主张识别准确率、主张—指标—期间匹配准确率、方向级一致性
  判断准确率、「不可直接比较」样本识别率、风险提示的精确率/召回率/F1
