## 一、五个构成项各自从哪来

```
I = 50 + 20·H + 20·C + 5·R − 10·P − 15·Q
```

| 项 | 含义 | 数据源 | 现状 |
|---|---|---|---|
| `H` | 历史主张兑现度 | 上一年度 MD&A 前瞻段的主张，与**下一年**实际结果比对 | 🟡 观测层已能产，缺跨年度聚合 |
| `C` | 当前一致性 | 本期 MD&A 主张与当期财务事实比对 | ✅ `engine/narrative.py` 已能产 |
| `R` | 风险披露变化 | 风险词频、不确定性模态词、风险段落长度与位置的变化 | ⬜ **无数据源**，需跨年度正文比对 |
| `P` | 模板化惩罚 | 文本高度模板化、缺少可验证指标 | ⬜ **无数据源**，需文本相似度 |
| `Q` | 财务质量冲突 | 勾稽异常、利润与现金流背离 | ⬜ **无数据源**，依赖 `engine/checks.py` |

> **`H` 为什么验下一年**：A-7 对 `H` 的定义是「上一年度 MD&A 前瞻性表述与**下一年度**
> 实际结果的匹配程度」。落地为 `rule_config.narrative.forward_verifies_next_year`。
> 不区分的话，前瞻主张会和本年数字比，方向多半对不上，于是**所有尚未到期的计划
> 都被判成冲突**——而那正是这个指数最该算对的一类。

## 二、观测怎么变成 `H` 与 `C`

### 2.1 分母只含三种状态

```
分母 = supported + partial + conflicted
```

`incomparable`（数据不可比）与 `missing`（缺数据）**既不计入分母，也不扣分**。
把「公司没披露」当成「叙事相悖」，等于替公司认了一个它没犯的错。

### 2.2 状态判定（`方案选择.docx` 第 10 条）

| 情形 | 判定 | 落地位置 |
|---|---|---|
| 实际方向与主张**相反** | `conflicted` | `index.direction.opposite_verdict` |
| 方向一致但**幅度较弱** | `partial` | `index.direction.weak_verdict` |
| 数据**不可比** | `incomparable` | `index.direction.incomparable_verdict` |
| 数值**未变动**（delta = 0） | `incomparable` | 本文 2.3 |

**判据只认方向，不设幅度阈值。** A-7 原文：

> 「20 个百分点」只适用于 MD&A 明确提出数值目标的情况。对于「需求增长」「回款改善」
> 等方向性表述，实际方向相反，直接标记为冲突。

> ⚠ **这里删过一道错误的闸门。** `engine/narrative.py` 曾经有一道
> `min_rel_change`（默认 1%）——「相对变动低于 1% 就当作没动」，
> 理由是宝钢 2019 年毛利率从 10.8791% 走到 10.8350%、动了 0.04 个百分点，
> 被判成「管理层说降本增效，事实相悖」看着荒唐。
>
> 挡掉的动机成立，**但那是拿工程直觉改会计口径**。已于 2026-09-26 删除，
> `rule_config.narrative.min_rel_change` 同步清掉。删掉后的实际影响：
> 宝钢 2020 年那两条（毛利率 10.8791% → 10.8350%）从「不可比」变成「冲突」，
> 全项目冲突数 8 → 10。
>
> 噪声该在「这句话够不够格被当成主张」那一层挡（词表与排除词），
> **不在判定这一层**——一条真实的反向主张因为「动得不够多」而免于被记成冲突时，
> 它在界面上与「数据缺失」长得一模一样，比误报更难发现。

### 2.3 数值未变动为什么不算冲突

`delta = 0` 时既没变好也没变坏，**没有方向可判**，归 `incomparable`。
主张说的是「会变好」，而它两个方向都不是——这与「方向相反」是两回事。

> 不设这道出口的话，`delta == 0` 会落进 `up if delta > 0 else down` 的 else 分支
> 被判成下行，**凭空多出一处冲突**。

### 2.4 各状态的计分权重

| 状态 | 权重 | 依据 |
|---|---|---|
| `supported` | `1.0` | `index.weight.supported`（暂定值，见第 6 节） |
| `partial` | `0.5` | `index.weight.partial`（暂定值） |
| `conflicted` | `-1.0` | `index.weight.conflicted`（暂定值） |

## 三、为什么现在不出分

**`R`、`P`、`Q` 三项没有数据源**，缺的是 **30 分权重**的构成项。

只算得出两项时就出分是最糟的选择：分母没变、权重照乘，
**出来的分与完整版一模一样**，看的人没有任何办法知道它少了三分之一。
所以当前界面只给观测与计数，并把不出分的原因写在卡片上（`index_note`）。

**出分的前置条件**：

1. `engine/checks.py` 落地（`Q` 的前置，甲）
2. `R`、`P` 的文本比对实现（乙）
3. 第 6 节里那批暂定参数经会计签字

**不是**「等 `docs/04` 落地」——公式早就定了，见本文件开头。

## 四、覆盖率闸门与分级

| 参数 | 值 | 含义 |
|---|---|---|
| `index.min_coverage` | `0.60` | 置信度加权覆盖率低于此值 → `grade='insufficient'`，**不出分** |
| `index.min_observations` | `5` | 进入分母的观测少于 5 条 → **不出分** |
| `index.grade_high_min` | `70` | `I ≥ 70` 一致性较高 |
| `index.grade_low_max` | `45` | `I < 45` 一致性较低，建议人工复核 |
| `index.grade_is_display_only` | `1` | **分级仅供展示**，不得宣称具有普遍预测意义，页面须明示 |

`grade='insufficient'` 时：只展示证据表 + 人工复核入口，**不改变任何估值参数**
（`mapping.insufficient.delta = {}`）。

## 五、传导至估值情景

诊断指数**不得黑箱式修改目标价**，只能通过预先公开的映射规则影响情景参数。
`map_index_to_scenario()` 是纯函数，返回各情景权重与参数增减，**绝不产出目标价**；
估值输出永远是区间。

| 分级 | 情景权重（基准/乐观/压力） | 参数调整 |
|---|---|---|
| 高 | `[0.60, 0.25, 0.15]` | 增速取历史中位数，WACC 与终值增长率不变 |
| 中 | `[0.50, 0.20, 0.30]` | 增速取历史下四分位，WACC +0.5 个百分点 |
| 低 | `[0.35, 0.15, 0.50]` | 增速取下四分位再打九折，WACC +1.0 个百分点，终值增长率 −0.5 个百分点 |
| 不足 | 不传导 | 不自动改变任何参数，只增加人工复核提示 |

### ⚠ 上表整张都是暂定值

**这四行里的每一个数字都没有会计文档依据。** 已逐份核对
`大框架-投研程序设计初版.docx`、`信息-搭建具体步骤.docx`、`方案选择.docx`、
`accounting_signoff_v1.docx`、`exclusion_terms_and_sentence.docx`——
五份文档对传导**只描述了方向**（「可提高基准情景权重」「或提高压力情景权重」），
**没有任何一个具体数字**。

这些数字是 2026-09-21 搭骨架时为实现 `map_index_to_scenario()` 先拍的，
却因为 `rule_config.tier` 默认 `hard` 而**看起来像会计口径**。
DCF 的情景权重直接决定估值区间，属会计/金融口径，**须经签字**。见第 6 节。

另有两条估值硬约束（同样待签）：

| 参数 | 值 | 含义 |
|---|---|---|
| `valuation.terminal_growth_max` | `0.02` | 周期行业不得给高永续增速，上限取长期通胀 |
| `valuation.wacc_min` | `0.06` | 防止压力情景下 WACC 被推到不切实际的水平 |
| `valuation.require_exit_multiple_check` | `1` | 永续增长法与退出倍数法结果须并列展示，对不齐时必须说明原因 |
