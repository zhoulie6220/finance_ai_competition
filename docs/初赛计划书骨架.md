## 一、项目概述

### 1.1 一句话

把上市公司年报里**管理层说过的话**拆成可验证的主张，与**后续真实的财务数字**
交叉验证，算出一个可解释、可追溯、可复算的「叙事—财务一致性诊断指数」，
再按**预先公开的映射规则**影响 DCF 估值的情景参数。

### 1.2 要解决的问题

传统投研工具做两件互不相干的事：一边算财务比率，一边做文本情感分析。
但真正有价值的问题没人回答——

> 管理层在 MD&A 里的表述是否可信？过去的承诺是否兑现？
> 本期叙事是否与财务结果一致？这种一致性是否应该改变估值假设？

### 1.3 核心原则

**数字由程序计算，模型只负责理解和组织文字。**

这条原则决定了系统架构：所有同比、勾稽、估值、评分都由确定性引擎（纯函数、
`Decimal`、零 IO）算出，大模型只做「把管理层的话拆成结构化主张」和
「把结论组织成可读的备忘录」。每一个数字都能点回到「文件 → 页码 → 原文」。

## 三、系统设计

### 3.1 三层输出结构

| 层 | 内容 | 呈现要求 |
|---|---|---|
| **事实** | 披露的数字 + 原文出处 | 每条带文件、页码、原文片段 |
| **推论** | 计算出的比率、一致性评分、估值区间 | 每条带公式与输入 |
| **观点** | 投资逻辑、风险判断 | 明确标注为观点，与上两层分开 |

赛事要求「明确区分事实、推论与观点」——这条在系统里不是文案约定，
而是数据契约的一部分：`evidence` 表的每一个指针都必须指到具体的一行。

### 3.2 七类模块 → 目录

赛事要求提交的源代码须包含「智能体编排框架、Tool、Prompt、Skill、MCP、
数据处理、日志记录」七类模块。对应关系：

| 技术要求 | 目录 |
|---|---|
| 智能体编排框架 | `backend/app/agents/` |
| Tool | `backend/app/tools/` + `backend/app/engine/` |
| Prompt | `backend/app/agents/llm/prompts/` |
| Skill | `backend/app/skills/` |
| MCP | `backend/app/mcp/` |
| 数据处理 | `backend/app/parsing/`、`engine/`、`db/`、`retrieval/` |
| 日志记录 | `backend/app/observability/` |

### 3.3 数据契约的十条硬约束

任何进入系统的财务数字必须同时具备十个字段：`metric / value / unit / period /
scope / source_file / source_page / source_text / confidence / status`。

其中三条落在数据库 CHECK 约束上，**不是写在文档里靠自觉**：

1. **无来源不得进已验证**——`status='validated'` 要求值与来源字段全部齐备
2. **缺失即无行**——不设默认值，绝不插补 0；「未找到」由视图生成
3. **不可比必须写原因**——`comparable=0` 时原因非空

第三条尤其重要：**缺失值填 0 看起来是最省事的「处理方式」，而且不会报错**——
毛利率会变成 −100%、现金转化率变成 0，而所有校验都通过。

## 四、核心方法

### 4.1 三表勾稽：从数字反推解析错在哪

年报解析一定会出错（跨页表、合并单元格、「其中：」层级行、负数括号、
单位只在表头出现一次），而**这些错误大部分不会让程序报错**——它们只是让
某个数字不对，然后一路流进比率和估值，最后变成一个看着合理但错的结论。

勾稽关系是唯一能自动抓住它们的办法。系统实现四条恒等式：

| 规则 | 公式 | 宝钢可查年度 |
|---|---|---|
| `bs_equation` | 资产 = 负债 + 所有者权益 | 2014–2018 |
| `cash_rollforward` | 期初现金 + 现金净增加 = 期末现金 | 2017–2024 |
| `cf_components` | 现金净增加 = 经营 + 投资 + 筹资净额 | 见下 |
| `gross_profit_check` | 毛利 = 营业收入 − 营业成本 | 见下 |

**不平优先怀疑解析错误，而不是公司造假。** 这是本项目反复强调的立场。

实测中这套校验照出了一个真实的字典缺口：现金流量表在「三项活动净额」与
「现金及现金等价物净增加额」之间有一行「汇率变动对现金及现金等价物的影响」，
字段字典里没有对应字段，导致 `cf_components` 在 2017–2024 每年都不平，
残差 −22 到 −292 百万元、逐年不同。**这不是解析错误，是字典缺字段**——
已定位到年报原文页，并据此把「不平」分成报表本身不平（error）与
字典缺字段（warn）两类分开呈现。

> 【待补】会计同学确认后补齐 `fx_effect_on_cash` 字段，该规则即可通过。

### 4.2 叙事—财务一致性诊断指数

```
I_raw = 50 + 20·H + 20·C + 5·R − 10·P − 15·Q
I     = min(100, max(0, I_raw))
```

| 分项 | 定义 | 取值 |
|---|---|---|
| **H** 历史兑现度 | 历史有效主张的判定值等权平均 | [−1, 1] |
| **C** 当期一致性 | 本期有效主张的判定值等权平均 | [−1, 1] |
| **R** 风险披露充分度 | 说明了风险对象、作用路径且给出依据的检查项占比 | [0, 1] |
| **P** 缺乏可验证性 | 无对象/期间/结果的实质表述占比 | [0, 1] |
| **Q** 财务质量冲突 | 已确认触发质量检查的独立事项占比 | [0, 1] |

**H、C 取 [−1, 1] 而非 [0, 1] 是刻意的工程决定。** 若五个分项都是 0–1，
中性证据只能取 0.5，于是 H=C=0.5 会算出 70 分——正好压在「一致性较高」的
分界线上，**全中性的公司反而得分最高**。改成 [−1, 1] 之后全中性得 50 分。

**四条件闸门**（全满足才出分）：

1. 覆盖率 n/N ≥ 0.60
2. 有效观测 n ≥ 5
3. H 与 C **各至少一条观测**
4. R、P、Q 均可计算且核验完成

不满足时输出 `insufficient_evidence`，指数为 **null**——
**不用 0 分或 50 分代替**。理由很实际：页面上出现一个大号数字，
人工复核的入口就没人看了。

### 4.3 噪声阈值：不同类型不能共用一个

金额与比例的量纲不同，共用一个阈值会让某一类的判定宽出两个数量级：

| 类型 | 噪声区间 | 说明 |
|---|---|---|
| 金额 / 数量 | 相对变化 ≤ **1%** | 基期为正且不接近零时 |
| 比例（0–1 存储） | 绝对变化 ≤ **0.5 个百分点** | 毛利率 10.00% → 9.96% 判无明显变化 |
| 周转天数 | 绝对变化 ≤ **3 天** | |
| 产能利用率 | 绝对变化 ≤ **1 个百分点** | |
| 明确数值目标 | **不套用统一容差** | 按原目标上下限与披露精度核验 |

**边界算噪声，严格大于才触发。** 而明确数值目标例外：「增长至少 5%」实际
增长 4% 必须判目标未达成，不能因为只差 1 个百分点就当作无明显变化。

### 4.4 指数 → 估值：只提示，不自动改

> **诊断指数不得黑箱式修改目标价**，只能通过预先公开的映射规则影响情景参数，
> 且**默认仅提示、由人工确认后重算**。

会计口径 v1.1 明确了这条边界，且它优先于早期的设计文档：

| 指数区间 | 工作台动作 | 估值动作 |
|---|---|---|
| ≥ 70 | 展示支持证据及仍存在的风险 | 保留原有情景，**不得自动提高增长率** |
| 45–70 | 展示争议项与假设敏感性 | **请求确认相关假设，不自动改值** |
| < 45 | 优先展开压力情景与反证条件 | **人工确认具体经营参数后重算** |
| 不足以出分 | 展示缺口与补资料入口 | 不发生由指数驱动的估值调整 |

**WACC 与永续增长率需要独立依据，不得仅因叙事指数低而修改。**

## 五、技术创新点

1. **不把「算不出来」混同于「算出来是零」**。缺失即无行、拒绝优于猜测、
   失败时中枢值强制为 NULL——三条都落在数据库 CHECK 约束上，而不是靠调用方自觉。
2. **勾稽校验反哺解析质量**。用报表内部的恒等式自动发现解析错误与字典缺口，
   而不是靠人工抽查。
3. **指数取 [−1,1] 而非 [0,1]**，避免中性证据获得最高分这一隐蔽缺陷。
4. **推论的每一步都带公式与输入**，使「点击结论回到计算过程」成为可能，
   而不是事后补的说明文字。
5. **离线回放模式**：现场断网时走预录响应，界面显著标注——
   把「不假装实时」当成工程约束而不是文案。

## 八、适用范围与风险

> 本节的表述直接采用会计负责人交付的成稿段落：

本项目以钢铁上市公司合并财务报表为基础，统一单位、报告期间、重述版本及损益
符号，并对重大重组和会计口径变化进行可比性复核。系统将 MD&A 拆解为具有明确
对象、期间和指标的主张，分别验证历史目标完成情况与本期叙事的一致性；金额数量
变化与比例变化采用不同的噪声过滤规则，未披露直接指标时不以代理指标强判冲突。
诊断指数是具有证据覆盖门槛的规则型研究工具，不代表管理层诚信、欺诈概率或股票
收益。估值按经营证据调整收入、成本及营运资本等对应假设，经人工确认后重算，
并保留调整前后参数与来源；不由指数自动修改折现率或永续增长率。

**明确不做的七件事**：实盘交易与自动下单；全市场实时行情与高频数据；
直接预测精确股价或承诺投资收益；依赖付费数据库才能运行的核心功能；
没有证据支撑的自动荐股；金融业公司分析；**把「叙事不一致」等同于「财务造假」**。

**统一展示口径**：

> 本结果为基于公开资料的研究辅助与风险提示，不构成审计意见或证券买卖建议。
