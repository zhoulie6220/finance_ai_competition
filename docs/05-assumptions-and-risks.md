# 主要假设、适用范围与风险

> **版本**：assumptions_risks_v1.1 ｜ **日期**：2026-09-26 ｜ **口径 owner**：会计 / 金融方向
>
> 本文由会计负责人交付的《指数、阈值、主题判据与减值口径》附件 B 转写入库。
> 原文为 docx，此前只在交付说明里被引用、仓库中并不存在。

## 一、适用范围

本项目定位为**钢铁上市公司公开财报、MD&A、情景估值和投研备忘录的辅助研究**，
**不替代审计、资产评估或投资决策**。

- 第一版面向**具有可读文本层年报的长流程 / 综合钢企**
- **不直接推广到银行、煤炭或其它行业**
- 研究案例采用 **2015—2024 年**历史材料，主要正常化窗口 **2017—2024 年**
- ⚠ **2024 年是历史案例终点，不是 2026 年的最新财务年度**

---

## 二、数据与时点假设

1. 每项事实保留**文件名、文件版本、页码、原文、原始单位、原始符号、标准化值、
   报告期和合并口径**
2. **估值必须另设 `analysis_as_of` 披露截止日**——
   2024 年度年报往往在 2025 年才披露，**不能声称在 2024 年底已经可得**
3. **只使用截止日前公开的信息**；历史重述数据保留版本，
   **不用后来披露的重述数冒充当时可得数**
4. 最近三年精细抽取，历史年份用于正常化；
   **不能声称仅三个字段就足以完成全部调整**，重大调整项目仍须定位附注复核
5. **数据缺失不是零，来源冲突不取简单多数**；
   优先同口径正式财务报表及相关附注，记录重述、四舍五入及差异
6. 人工录入须注明原始资料和复核人；
   **构造案例仅作测试，禁止冒充年报原文**

---

## 三、会计假设

- 以**合并报表**为主，不混用母公司数据
- 单位、期间、本期上期、重述版本**先统一后比较**
- **应收合并行与拆分行建立互斥计算关系，不能重复累计**
- 票据结算变化**单独解释**
- 资产减值采用 `loss_positive`（见 `docs/04-index-rules.md` §二）
- ⚠ **正负号统一与经济可比性是两回事**——
  新金融工具准则前后的资产减值、信用减值分类可能不同，
  须另作**重分类桥接**
- 保留经常性经营损耗，异常减值 / 投资收益 / 政府补助 / 资产处置 / 套保损益
  **逐项分析，不按科目名称一律剔除**
- EBIT 及调整后 EBIT 提供**计算桥接表**，
  **不将财务费用直接等同利息费用**，不把同一减值重复加回
- 重大资产注入 / 并购 / 业务剥离 / 政策变化导致不可比时**先标记**；
  **不可恢复可比性则不强制输出正常化估值**

---

## 四、叙事诊断的局限

- 管理层文字与财务事实的一致性**不等于披露真实性，更不等于股价涨跌**
- **词频只能帮助检索主题，不能独立判定风险、意图、欺诈或经营成果**
- 采用同对象、同期间、同口径的**直接指标**
- **未到期目标不提前判失败**
- **1% 及 0.5 个百分点等阈值为初赛噪声过滤参数，不是审计重要性水平**
- 指数是规则型诊断，**权重和 70 / 45 分级线未经大样本校准**；
  **至少 5 条观测仅为演示门槛**
- 大模型仅提取候选主张和辅助解释；
  **数值、公式、证据及最终判定由确定性规则与人工复核约束**

---

## 五、估值假设

- DCF 使用明确的 FCFF、所得税、折旧摊销、资本开支、营运资本变动、WACC 及终值假设
- 从企业价值到权益价值另列净债务、非经营资产及少数股东权益等适用调整，
  明确股本口径
- **周期中枢不是未来保证值；八年或十年窗口也不天然保证覆盖完整经济周期**，
  须展示历史盈利高低点及行业背景
- **终值增长率须低于 WACC**，永续资本开支及营运资本假设须支持经营持续性
- 情景分别披露参数与敏感性，**不用单点目标价隐藏不确定性**
- 相对估值须核对业务、会计口径和估值时点
- **指数不自动改变 WACC 或永续增长率**；
  只有可追溯的经营证据和人工确认才能改变对应经营假设

## 六、风险与控制清单

| 风险 | 控制措施 |
|---|---|
| PDF 单位 / 跨页 / 列错位 / 负号错误 | 原文回链、**勾稽检查**、保留 raw_value、`needs_review` |
| 扫描件或附注漏取 | 单独 OCR 或人工录入复核，**不承诺全自动** |
| 周期及价格混杂 | 优先直接指标，展示价格 / 数量 / 成本拆解 |
| 并购、口径变化与重述 | 可比性标签、重述桥接、必要时**拒绝出分** |
| 未来信息泄漏 | **按公开披露日期冻结材料与模型输入** |
| 样本少和人工标注分歧 | 双人标注、留出验证、**报告样本数与分歧** |
| 模型幻觉及文档提示注入 | **文档仅作数据**，公式工具计算，引用强校验 |
| 情景与终值假设偏差 | 区间及敏感性展示、假设批准记录 |
| 第三方服务断网 | 本地缓存已核验案例，**明确「缓存回放」，不伪装实时** |
| 数据授权与 API 泄密 | 密钥仅后端环境配置，不上传无权共享资料 |

## 七、复核门槛与对外表述

- **`validated` 表示字段值及来源经过既定核验，
  不代表整份报告或公司财务没有问题**
- **已判定准确率、自动覆盖率、人工复核比例分别报告，
  不能仅报「准确率高」**
- 证据不足、历史不可比、重要字段缺失、指数闸门不满足时**明确说明，
  不以猜测补齐**
- **统一展示**：

> 本结果为基于公开资料的研究辅助与风险提示，不构成审计意见或证券买卖建议。

## 八、本项目的实现落点

上面这些约束不是靠文档约定，多数已经落到代码与数据库约束上：

| 假设 / 风险 | 实现位置 |
|---|---|
| 缺失即无行，绝不插补 0 | `financial_fact` 无默认值；「未找到」由 `v_fact_grid` 视图生成 |
| 无来源不得进已验证 | `financial_fact` 的 CHECK 约束 |
| 不可比必须写原因 | `financial_fact` 的 CHECK 约束 |
| 指数与估值只读已验证事实 | `v_fact_verified` 视图 |
| 指数闸门不过时不得出分 | `diagnosis_run` 的 CHECK 约束 + 引擎 `_fail` 模式 |
| 周期覆盖不完整时拒绝输出中枢 | `normalization_run` 的 CHECK 约束 |
| 未来信息泄漏 | `narrative.forward_verifies_next_year` 决定前瞻主张用下一年度验证 |
| 模型幻觉（编造数字） | `app/agents/guards.py` 数字守卫 |
| 断网 | `OFFLINE_MODE` + cassette 回放，界面显著标注 |
| 密钥泄密 | 密钥只从 `LlmSettings` 读，不进 `llm_call.params`、不进日志 |
| 结果可复现 | 引擎纯函数 + `run_manifest` 记录代码版本、依赖哈希、规则版本、随机种子 |

**测试即约束的看门人**：上述每一条都有对应的自动化测试，
其中不少是**刻意的反例测试**（构造一个必须被判失败的输入）——
只断言「真实数据通过」是不够的，因为「规则没生效」和「数据恰好干净」
看起来一模一样。
